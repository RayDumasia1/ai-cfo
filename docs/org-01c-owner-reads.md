## Bounded scope

Convert monthly financial-data **reads** first. Financial Data uses an authenticated, organization-scoped RPC; a verified owner can discover its own workspace through `/api/organizations` and select it with `?organization_id=<uuid>`. Default selection is derived from the caller's checked legacy profile/mapping. There is one eligible owner workspace per legacy account; no new switcher UI, memberships, invitations, professional clients, advisor access or saved browser selector is introduced.

The read context requires the same actor across Auth, profile, legacy mapping and original owner membership; active customer/legacy-shadow organization; live mapping; fixed owner/origin; and current revisions. B's `legacy_shadow` label alone grants nothing. The explicitly installed C resolver and domain-specific RLS policy authorize only the original legacy owner's monthly read. No actor parameter, role, paid tier or legacy-owner ID from the browser is trusted. Unknown capabilities and foreign selectors fail closed.

The Financial Data page no longer gates on the viewer's personal subscription before resolving scope. The database checks the subscription attached to the selected workspace's checked legacy owner: active/pending cancellation, an eligible tier and the current paid-account predicate. This is a temporary explicit legacy billing bridge, not a new billing-account model. Nonowners remain denied regardless of their own plan. Workspace discovery can remain available to a verified owner after lapse; it returns only its own ID/current business name. It does not return financial data or payment details. Missing/invalid evidence never creates permission; reading stale financial history remains allowed when authorized.

## Why this domain

Profile SELECT is also used by existing authenticated INSERT/UPDATE RETURNING paths. An organization-dependent profile SELECT policy could run before the B AFTER INSERT provisioning hook, breaking legitimate profile creation. C therefore leaves profile policies and write paths alone. Monthly browser access is SELECT-only; existing service-side imports retain their profile locks and write semantics. C replaces the monthly table's old ALL policy rather than layering a permissive organization policy beside it.

Before installing C, all live profiles must have valid B identity, and every monthly row must have the matching non-null business-profile/account scope. Missing/foreign scope aborts installation without repairing history. Future malformed service-written rows are hidden by RLS; the converted RPC reports an integrity/unavailable state instead of silently presenting them as an empty dataset. The current preview's monthly scope inventory is clean. Its 12 legacy actions with null business links remain untouched for D; the earlier B inventory recorded nine at that time.

## Read contracts

- The SQL functions bind `auth.uid()` and require verified Auth email. Authenticated callers cannot supply another actor. Service role is not granted RPC execution; it retains existing trusted direct-read behavior under BYPASSRLS. The RLS predicate exposes a boolean for the caller's own row scope, never another workspace's metadata.
- A closed, versioned context carries actor, organization, preserved profile, original membership/revision, organization revision, capability `financial.months.read`, opaque data version and selected workspace tier. It is request-scoped, not a durable authorization token. No Stripe IDs, payer identity or provider credentials are returned.
- The server adapter checks actor/selected-organization parity, context version and every returned month's scope. It preserves rows, numeric/null values, source metadata, ordering and financial meaning. Bounded reads support 1–240 rows; null limit requests full supported history and fails if it exceeds 240 rather than truncating silently.
- A genuinely absent profile returns a setup state and the page returns to the existing dashboard setup flow. Missing mapping, bad graph, missing migration or bad payload is an unavailable state, never a legacy-query fallback or fabricated empty account. A lapsed workspace redirects to the existing plan-selection flow. Foreign/malformed selectors produce a non-enumerating not-found response.
- The page resolves authorization before loading its still-account-scoped import history. The context is explicitly owner-only, so actor equals the legacy account; it never substitutes a different owner's account as the acting user. No C context is passed to unchanged write APIs.
- Requests are uncached. Selection is explicit per request; there is no process-global or browser-persisted active organization. Unavailable/foreign selections do not fall back to another organization. The proxy exemptions are exact paths; their handlers/resolver retain Auth, verification and target entitlement enforcement.

## Required acceptance

Owner list/default/explicit selection parity; exact monthly rows/order/nulls; foreign organization rejection despite paid higher tier; direct SQL/RLS isolation; no anonymous/unverified access; pending-cancellation paid behavior; suspension/lapse denial; missing-profile versus missing-mapping distinction; no setup writes on reads; no profile-creation regression; no extra service/browser table/function privileges; invalid/duplicate selectors and limits; stale context/response-scope rejection; unavailable migration behavior; no cache or shared client state; unchanged billing, usage, financial values, imports, forecasts and action ordering.

C is an owner-only compatibility bridge. Organization-owned financial FKs, write authorization, per-user suspension, team roles, billing-account coverage and collaboration still require D/E and a versioned resolver change. Existing service-role consumers remain trusted legacy paths, not newly delegated access. Revocation/deletion takes effect on subsequent statements; C does not retract data already delivered under a prior database snapshot. B's profile-first hooks remain intact because C adds no mutating organization-lock path.
